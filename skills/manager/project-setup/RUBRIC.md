# Rubric: Project Setup

## Passing Standard

The output passes if it:

- accurately reflects the current project state
- proposes an additive, minimal structure
- defines a project-specific config with team roster, source keywords, source map, update cadence, and decision-log rules
- establishes a living Research Design and Progress document or equivalent project-design progress artifact
- records decisions in the project artifact system rather than leaving them only in chat
- identifies the core artifacts needed for downstream workflows
- maps real external systems instead of hypothetical ones
- preserves the distinction between manager coordination and required data-science workflow gates
- flags risks and missing inputs clearly

## Failure Modes

Fail if the output:

- assumes a structure without inspecting the project
- proposes reorganization without user approval
- omits source-of-truth documents or update locations
- omits team roster, source keywords, decision log, or Research Design and Progress artifact
- treats chat history as a sufficient decision record
- lets weekly review or stakeholder update proceed without a usable project config
- starts analysis or modeling before required workflow gates exist
- ignores sensitive-data constraints
- marks the project ready when key dependencies are missing
