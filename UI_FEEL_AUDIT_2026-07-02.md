# UI / Visual-Feel Audit — 2026-07-02

**Scope:** typography, color, spacing/rhythm, motion, component consistency, dark/light behavior, visual accessibility, overall polish. Content, navigation, and link findings live in `AUDIT_REPORT_2026-07-02.md` and are not repeated here. Nothing below reverses the June 2026 design decisions (amber CTAs on dark sections, 180ms cubic-bezier bubble hover, role-grid breakpoints, decision-grid cards) — several fixes *extend* those decisions to the places that never adopted them.

## Summary

The site has a genuinely coherent design language on paper — DM Sans / JetBrains Mono / Fraunces, a warm slate dark mode (`--md-hue: 190`), teal accents on light surfaces, amber CTAs on dark ones, and a documented 180ms `cubic-bezier(0.2, 0, 0, 1)` motion token. The problem is that the language is only fully spoken in `extra.css` and the homepage. The interactive "dark terminal" widgets — the site's most distinctive component, appearing on the quickstart, both learning lenses, the live-session page, the manager/execution lenses, and six workflow gate pages — exist only as ~200 copy-pasted inline `style` attributes with no shared classes. The copies have drifted (two different muted grays, mono sizes at 0.82/0.83/0.84/0.85/0.87rem, mixed px/rem padding), the muted slate labels fail WCAG AA contrast on their navy backgrounds exactly where they carry instructional weight, transition timings scatter across 150/200/220/350ms while the standard says 180ms, and there is no `prefers-reduced-motion` support anywhere despite scroll-reveal animations and a JS parallax hero. All of this is fixable without redesigning anything: extract the terminal palette into shared classes, bump three grays, add one media query, and align the timing tokens.

## Deeper findings

**1. One component, ten forks.** The dark terminal is the site's signature — it's how the homepage's "proof of utility" promise is made tangible on interior pages. But it was never built as a component: each page re-declares the full palette (`#0d1b2e` shell, `#1a2f4a` chrome, `#3bc9db` cyan commands, `#f4a261` amber questions, `#a6e3a1` green outputs) inline. The forks have measurably drifted — the two *learning lenses*, which are supposed to be the same experience for two datasets, already disagree on nothing visible but agree only by luck; the manager/workflow pages have diverged further (0.83 vs 0.82rem shells, `#6c7a8d` vs `#4a6885` labels, different textarea borders `#1e3a5a` vs `#1e3a5f`). Every future example page will fork again unless the palette lives in `extra.css`. This pass extracts the classes and converts the two learning lenses; the remaining eight pages are a mechanical follow-up.

**2. The contrast failures land on the pedagogy.** The failing grays aren't decorative — they label the widget's interaction contract: *Codex asks* → *Your attempt* → *Codex output*. A low-vision student literally can't read the part of the UI that explains attempt-before-answer, the site's core teaching promise. At ~3.0:1 and 0.72rem uppercase, `#4a6885` fails AA by a wide margin. `#7d90a8` keeps the same desaturated slate-blue character at ≈5.3:1, so the fix is invisible to most users and decisive for the ones it matters to.

**3. The motion system is documented but not deployed.** The June 2026 pass established `180ms cubic-bezier(0.2, 0, 0, 1)` and applied it to `.hf-bubble` transforms and `.decision-card`. Everything older kept its ad-hoc timing (150ms, 0.2s, 200ms, 350ms), and even `.hf-bubble` itself mixes tokens within one declaration (180ms transform + 200ms border). Meanwhile the accessibility half of a motion system — `prefers-reduced-motion` — is entirely absent, which matters here more than on most doc sites because the homepage combines scroll-linked parallax with translateY reveals (a known vestibular trigger, WCAG 2.3.3). One media query closes the gap for everything except the JS-driven 350ms answer fade inside the classification widget (inline style; needs a JS touch that is out of scope for this pass).

**4. The homepage's design language *does* carry inward — through exactly one thread.** Fraunces headings, teal page titles, and the amber/cyan/navy terminal palette give interior pages real continuity with the hero (amber = Codex speaking everywhere; cyan = commands everywhere). That's better coherence than most MkDocs sites achieve. The gap is that this terminal palette — arguably more load-bearing than the amber CTA that *is* documented — appears in zero stylesheets and zero standards docs. Once the `.cb-*` classes exist, one line in `ui-ux-standards.md`'s Design Decisions section would make it official.

**5. Micro-typography noise.** Across inline widgets the body-copy sizes sample almost every value from 0.78 to 0.90rem (0.8, 0.81, 0.82, 0.83, 0.84, 0.85, 0.87, 0.88, 0.9) and eyebrow labels sample 0.68–0.78rem. No single instance looks wrong; together they make sibling components feel subtly unrelated. The shared classes collapse the learning-lens instances to one scale (0.85 command / 0.87 question / 0.84 answer / 0.72 eyebrow — the majority values); the remaining pages should adopt the same scale when they're converted.

## Ranked fix list

### Safe now (implemented on this branch)

1. **Extract shared terminal classes** (`.cb-terminal`, `.cb-term-*`, `.cb-btn*`) into `extra.css`; convert both learning-lens widgets to them — visually identical extraction first, then normalization.
2. **Contrast bump**: `#4a6885` / `#6c7a8d` → `#7d90a8` in the shared classes and in the inline styles of live-session, manager/execution lenses, workflow gate pages, and textbook-resources (pure color-value substitution; quickstart's protected lines and the SVGs excluded).
3. **`prefers-reduced-motion` block**: reveals forced visible, parallax neutralized, banner keyframe and hover lifts disabled.
4. **Timing harmonization** to `180ms cubic-bezier(0.2, 0, 0, 1)`: `.bento-cell`, `.grid.cards` li, `.hf-bubble` border-color, `.qs-tab`, widget textarea focus.
5. **Responsive**: `.qs-cmd` `overflow-x:auto` + `max-width:100%`; quickstart comparison grid stacks at 600px; `.cb-terminal` padding/min-height relaxation ≤480px.
6. **Focus/disabled affordances** on `.cb-btn` (`:focus-visible` outline, `:disabled` opacity).
7. **Remove dead `#claude-blattman` selector.**
