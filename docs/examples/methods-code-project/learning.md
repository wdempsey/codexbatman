# Methods / Code Project — Learning Lens

Use this lens when the goal is to understand why technical code work still needs backbone artifacts.

## What The Learner Should Understand

- why repository complexity makes durable project memory more important, not less
- why code exploration is not the same as scientific review
- why handoffs matter in methods/code projects
- why decisions about simulation design and evaluation should be logged

## Reflection Questions

1. What information belongs in `decision_log.md` instead of code comments?
2. Why might `workflow_trace.md` be especially useful in a methods-heavy repository?
3. What questions can structural code memory answer, and what can it not answer?

## Artifact Purpose

- `PROJECT_STATE.md` tracks the current technical objective.
- `decision_log.md` records why architecture or experiment choices were made.
- `workflow_trace.md` records what was explored in the repository.
- `HANDOFF.md` prevents each new session from starting blind.
