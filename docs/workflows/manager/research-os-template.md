# Research OS Template

These templates provide the folder-first artifact layer for the Research OS / Lab Manager system.

They are designed to support portfolio visibility, project coordination, handoffs, deadlines, and weekly review without turning the system into a separate application.

## Template Locations

Lab-level templates:

- [`templates/research-os`](https://github.com/wdempsey/codexbatman/tree/main/templates/research-os)

Project-level templates:

- [`templates/research-os/project`](https://github.com/wdempsey/codexbatman/tree/main/templates/research-os/project)

## Lab-Level Templates

The lab-level template set supports:

- portfolio visibility
- deadlines
- waiting-on lists
- people-to-project mapping
- weekly review
- communication norms
- agent operating rules

Included files:

```text
LAB_DASHBOARD.md
ACTIVE_PROJECTS.md
PEOPLE.md
DEADLINES.md
WAITING_ON.md
WEEKLY_REVIEW.md
COMMUNICATION_POLICY.md
AGENT_OPERATING_RULES.md
```

## Project-Level Templates

The project-level template set supports:

- project brief
- current status
- next actions
- decisions
- handoffs
- agent instructions

Included files:

```text
PROJECT_BRIEF.md
PROJECT_STATE.md
NEXT_ACTIONS.md
DECISIONS.md
HANDOFF.md
AGENTS.md
```

## How To Use These Templates

Recommended approach:

1. Use the lab-level files to maintain portfolio memory.
2. Use one project-level template folder per active project.
3. Point Lab Manager review workflows back to the project files rather than summarizing from memory.
4. Keep communication policy explicit and human-supervised.

## Why These Templates Exist

The Backbone Protocol handles one project's analytical memory.

The Research OS templates handle the next layer up:

- many projects
- many people
- many deadlines
- many handoffs

Together they support a system where project work remains durable and portfolio review remains manageable.
